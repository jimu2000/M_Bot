# 阶段 5 待做清单（工作包 E 标注）

阶段 5「补齐缺口」工作包 E 已实现的功能见各模块 docstring 与 README；
本文件只记**明确标注待做、不实现**的两项（深度研究新增缺口里的低优先级项）。

## 待做（不实现）

### 1. 主机按 IP 解析会话（R-Bot `/host/sessions/resolve-by-ip`）

- R-Bot 行为：按 IP 查该主机当前有没有活动的 SSH 会话，有则返回会话 id，
  前端直接跳到已有会话，不用重复建连接。
- 不做的原因：
  - 克隆版的 SSH 会话只在内存里（`web/ssh.py` 的 `SSHSessionManager`），
    会话记录本身没有“属于哪台已保存主机”的稳定映射——手动输入 IP 建的
    会话与 hosts.json 里的主机是两套东西，要解析就得先给每条会话补
    host 归属字段，再处理“同一 IP 多个会话”（不同用户/端口）与
    “会话已断但未清理”的边界，工作量不小。
  - 收益低：终端页的标签栏已经列出全部活动会话，用户一眼能看到；
    重复建连接的成本只是一次 SSH 握手，且空闲会话 30 分钟自动清理。
  - 如将来要做：给 `SSHSessionManager` 的会话记录加 `host`/`port`/
    `username` 字段，`resolve-by-ip` 按 IP 匹配未关闭会话，多个时
    返回最近活动的那个；前端在连接前先调该接口，有会话则直接切标签。

### 2. 终端粘贴图片（R-Bot `/terminal/paste-image`）

- R-Bot 行为：终端里粘贴图片时，图片经该接口上传到远端主机（或转存后
  在终端里以某种形式使用）。
- 不做的原因：
  - 需前端剪贴板 API（`navigator.clipboard.read` / paste 事件的
    `clipboardData.items`）读图片数据，浏览器权限模型下剪贴板读图片
    需要用户明确授权且只在安全上下文（HTTPS/localhost）可用，面板
    常走 SSH 隧道 + `http://127.0.0.1`，可用性没保障。
  - 图片到了远端之后“怎么用”没有统一语义：贴到终端里不能显示，只能
    存成文件；存文件已有 SFTP 上传（单次 + 分块带进度），路径更直接。
  - 工作量与收益不成正比：要做剪贴板读取、图片格式校验、上传通道、
    远端落盘路径约定、终端内反馈，一整条链路只为了“粘贴图片”这一个
    入口，而 SFTP 上传已经覆盖了传文件的需求。
  - 如将来要做：前端监听终端的 paste 事件，检测到图片时走
    `/api/ssh/sessions/{id}/sftp/upload`（复用现有上传接口，不必新开
    `/terminal/paste-image`），落到远端家目录并提示路径；剪贴板读不到
    时静默降级为不处理。
